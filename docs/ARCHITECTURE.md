# DunkHub — архитектурные решения

## Платформа

Standalone веб-приложение (React + Vite, PWA) — без Telegram Mini App.
Решение принято сознательно: Telegram-путь требует бота (BotFather),
хостинга с публичным HTTPS и токенов третьих сторон до того, как можно
проверить хоть что-то на реальном устройстве — это блокировало разработку.
Как только появится инфраструктура для деплоя, Mini App можно вернуть как
второй способ входа (тот же код, дополнительный auth-провайдер), но это не
блокирует MVP.

Авторизация — email + пароль, свой JWT (HMAC-подписанный, без внешних
библиотек — см. `apps/api/src/auth.ts`), пароли хешируются `scrypt`
(node:crypto, без внешних зависимостей). Токен живёт в localStorage
фронтенда и передаётся как `Authorization: Bearer`.

## Замер прыжка

On-device pose estimation (MediaPipe Pose Landmarker, WASM/GPU-delegate),
без отправки видео на сервер. Высота считается по времени полёта
(flight time), которое определяется по вертикальной скорости
условного центра масс (среднее по landmark бёдер) — see `JumpMeasure.tsx`.
Это прототип алгоритма детекции взлёта/приземления, а не финальная
калибровка точности — требует валидации на реальных прыжках и, возможно,
калибровки по росту пользователя перед тем, как показывать пользователю
абсолютные цифры без диапазона погрешности.

Открытый риск: производительность pose-detection в мобильном браузере
на среднебюджетных Android-устройствах не проверена — это первое, что
нужно протестировать на реальных телефонах перед тем, как расширять
функциональность замера (approach jump, reactive jump). getUserMedia
работает без HTTPS только на `localhost`, так что для теста на телефоне
всё равно понадобится либо туннель (ngrok/cloudflared), либо деплой с
HTTPS — сам по себе отказ от Telegram эту часть не снимает.

## Профилактика травм

- `leftKneeValgusRatio` / `rightKneeValgusRatio` на `JumpMeasurement` —
  фронтальная проекция отклонения колена от линии бедро-голеностоп в
  момент приземления, proxy для valgus collapse (маркер риска ACL).
- `GET /injury-risk` — ACWR (7 дней vs скользящее среднее за 28 дней по
  количеству прыжков) с бандами риска + средняя асимметрия колен по
  последним 10 прыжкам.
- `RecoveryCheckin` — дневной чек-ин (боль, сон, RPE), один активный на
  день (повторная отправка в тот же день перезаписывает, не создаёт дубль).

## Согласие на использование данных

Согласие — обязательное условие для записи `JumpMeasurement`
(проверяется в `POST /jumps` в apps/api/src/server.ts). Хранится как
версионируемая запись `ConsentRecord` (scope + version + timestamp),
чтобы при изменении политики можно было запросить согласие заново, не
теряя историю прежних согласий.

## Что дальше (не реализовано)

- Тренировочные программы (content service).
- Community/leaderboard.
- Возврат Telegram Mini App как второго входа, когда появится
  инфраструктура для деплоя.
